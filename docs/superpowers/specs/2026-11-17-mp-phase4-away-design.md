# Фаза 4: «ходите без меня», разгон активностей, длительности отсчётов — дизайн

Дата: 2026-11-17
Статус: на утверждении
Родитель: `2026-08-04-cdda-p2p-coop-design.md`, §7.4, §7.5, §8.5, §11

## 1. Зачем

Критерий Ф4 из родительского спека: **сон до утра за секунды; AFK не морозит сессию.**
Вечер вдвоём упирается в две вещи, которые планировщик Ф3a намеренно не решал:

- игрок, отошедший за чаем, держит барьер, пока не истечёт «тороплю» — то есть партнёр
  каждые пятнадцать секунд должен просить мир ехать дальше;
- никто не проверял, что долгая активность действительно проскакивает быстро: это
  получается как побочный эффект резюмируемого хода (`do_turn.cpp:761`), и не измерено.

## 2. Что уже есть (проверено по коду)

| Есть | Где |
|---|---|
| Состояния `acting`/`acted`/`holding`/`not_waited`, барьер, drop по отсчёту, сжигание ходов у drop | `src/mp/mp_turn.{h,cpp}` |
| Активность или назначенный маршрут = `acted`, поэтому барьер закрывается сразу | `mp_turn.cpp:103-106` |
| Отсчёты «тороплю» и боевой, автоматический боевой | `mp_turn.h:10,12`, `mp_tick_hurry()` |
| Строка «waiting: X (n)» в мировой панели, уезжает клиенту в кадре | `src/display.cpp:1343-1369` |
| Клавиша «тороплю» (`coop_hurry`, `` ` ``) | `data/raw/keybindings.json`, `handle_action.cpp:3472` |

Из этого следует, что `status`-сообщение из §5.2 родительского спека **не нужно**: панель
уже рисуется сервером под контекстом каждого игрока и приходит в кадре. Отдельный канал
был бы вторым источником правды о том же самом.

## 3. Чего нет

- Липкого «ходите без меня»: ни состояния, ни клавиши, ни возврата.
- Ограничения свободного прогона: сейчас `mp_turn_paced()` возвращает `false`, если у
  живого игрока нет активности и он не left-behind (`mp_turn.cpp:196-208`). Ушедший игрок
  без активности — ровно этот случай, то есть мир поедет на скорости CPU, пока все пьют чай.
- Проверки, что долгая активность проскакивает быстро.
- Настраиваемых длительностей: `MP_HURRY_MS` и `MP_HURRY_COMBAT_MS` — константы.

## 4. Подходы

| | Один ушёл, второй играет | Ушли все | Итог |
|---|---|---|---|
| **A.** AFK = добровольный drop (как `not_waited`) | второй идёт в своём темпе | отсчёт 15 с на тик, мир ползёт сам | отвергнут: пустая сессия всё равно тикает |
| **B.** AFK = `acted` | то же | мир на скорости CPU до утра | отвергнут: «ушёл» становится кнопкой перемотки мира |
| **C.** A + «все живые ушли — ход не закрывается» | второй идёт в своём темпе | мир стоит, пока кто-то не вернётся | **выбран** |

Почему C: ушедший не мешает и не эксплуатируется (шаг пропущен, ходы сожжены — как у
drop), а свободный прогон остаётся только у того, кто о времени попросил: сон, крафт,
маршрут. Пустая сессия не перематывает мир втихую.

## 5. Решения, принятые при брейншторме

1. **Уйти — отдельная клавиша**, симметричная `coop_hurry`: новое действие `coop_away`,
   по умолчанию `:` (в `DEFAULTMODE` не занята; `?`, `,`, `<`, `>` заняты в других
   контекстах, `~` — в `DEFAULTMODE` у `ignore_enemy`/`whitelist_enemy`).
2. **Вернуться — значимое действие, а не любое нажатие.** Уточнение против того, что
   обсуждалось: любое нажатие возвращало бы в барьер игрока, листающего инвентарь или
   читающего сообщения, — то есть ровно тот баг, из-за которого `mp_turn_reset()` не
   трогает флаги ввода (`mp_turn.h:60-77`). Свободные действия (`mp_action_is_free()`)
   away не снимают; снимают его действие, тратящее ход, и сама клавиша `coop_away`
   (повторное нажатие).
3. **Бой не даёт разгоняться мимо ушедшего.** Если враждебное существо видит кого-то из
   игроков, а кто-то ушёл, ход закрывается не быстрее боевого отсчёта — иначе ушедшего
   съедят за один кадр, пока партнёр крафтит.
4. **Длительности — флаги сервера** `--hurry-ms` и `--hurry-combat-ms`; файл конфигурации
   остаётся за Ф5 (§8.5: «командная строка плюс файл»), и он будет читать те же сеттеры.

## 6. Дизайн

### 6.1 Состояние

В `mp_turn` — флаг `g_away[slot]`, рядом с `g_dropped_by_countdown`. Хранится, а не
выводится: это единственное состояние модуля, которое игрок объявил сам, и из игры его
не восстановить.

`mp_player_state` получает значение `away`, которое проверяется **первым** в
`mp_player_state_of()`: ушедший не держит барьер независимо от активности и ходов.

- `mp_turn_reset()` away **не снимает** (в отличие от drop и отсчётов) — иначе режим
  прожил бы ровно один тик. `mp_turn_reset_all()` снимает: старт сессии и тесты.
- `mp_barrier_satisfied()` считает `away` удовлетворённым (как `not_waited`).
- `mp_forfeit_dropped_moves()` сжигает ходы и у `away`: ушедший не копит ходы, иначе
  возвращается с минутным запасом и делает шестьдесят действий в одном тике.

### 6.2 Новый API `mp_turn`

```cpp
void mp_set_away( size_t slot, bool away );   // клавиша coop_away
bool mp_player_is_away( size_t slot );        // панель и тесты
void mp_return_from_away( size_t slot );      // вызывается на действии, тратящем ход
bool mp_turn_all_away();                      // все живые ушли
void mp_set_hurry_lengths( int manual_ms, int combat_ms ); // флаги сервера
```

### 6.3 Цикл хода

`do_turn.cpp:761`:

```cpp
while( !mp_barrier_satisfied() || mp_turn_paced() || mp_turn_all_away() ) {
```

При `mp_turn_all_away()` барьер удовлетворён, `moved` ложно, цикл уходит в
`wait_for_request( MP_POLL_MS, owes_turn )` и возвращает `false`: ход остаётся открытым,
мир не тикает. Возвращение игрока снимает away, он попадает в `owes_turn` как `holding`,
и ход закрывается обычным порядком.

`mp_turn_paced()` получает второе условие: кто-то ушёл и кого-то видит враждебное
существо — держать ход не меньше боевого отсчёта.

### 6.4 Ввод

- `handle_action.cpp`, рядом с веткой `ACTION_COOP_HURRY`: `ACTION_COOP_AWAY` →
  `mp_set_away( active_slot, !away )`, действие свободное (`mp_action_is_free`).
- Там же, после проверки «уже действовал»: если действие не свободное и игрок ушёл —
  `mp_return_from_away()` до выполнения. Ход при этом тратится как обычно.

### 6.5 Панель

`display::coop_player_text()`: к строке «waiting: A, B (12)» добавляется «away: C», когда
кто-то ушёл. Ушедший не попадает в список ожидаемых. Формат — одна строка, потому что
панель узкая.

### 6.6 Длительности

`MP_HURRY_MS`/`MP_HURRY_COMBAT_MS` становятся значениями по умолчанию для двух
переменных модуля; `mp_set_hurry_lengths()` вызывается один раз при старте сессии из
`cli_opts`. Ноль и отрицательное — отказ с сообщением сервера, а не тихое значение.

## 7. Проверка

- `tests/mp_turn_test.cpp`: away не держит барьер; away переживает `mp_turn_reset()` и
  снимается `mp_turn_reset_all()`; ходы ушедшего сожжены; свободное действие away не
  снимает, тратящее — снимает; `mp_turn_all_away()` на смешанном составе ложно.
- `tests/mp_session_test.cpp` (харнесс, два клиента): один ушёл — партнёр играет без
  остановок; оба ушли — календарь не двигается за N опросов; вернувшийся действием
  получает ход.
- Разгон: оба игрока с активностями — за ограниченное время закрывается много ходов
  (доказательство критерия «сон до утра за секунды»). Порог generous: это проверка
  порядка, а не бенчмарк.
- Бой: ушедший в поле зрения монстра не даёт миру разгоняться.

## 8. Не-цели

- Сервер **не играет** за ушедшего и не отдаёт его NPC: это Ф5 (§8.4, «льготный интервал
  до перевода отвалившегося в npc»).
- Нет таймера, который сам возвращает игрока или снимает away по времени.
- Нет отдельного протокольного сообщения `status`: панель уже в кадре.
- Файл конфигурации сервера — Ф5.

## 9. Что остаётся реализующему

- Клавиша по умолчанию и тексты сообщений («вы отошли», «вернулись») — на его вкус,
  в рамках §6.4.
- Порог «много ходов за ограниченное время» в тесте разгона.
