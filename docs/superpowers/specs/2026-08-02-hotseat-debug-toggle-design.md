# Debug-переключатель hotseat-коопа для плейтеста — дизайн

Дата: 2026-08-02
Статус: утверждён к планированию
Родительский план: `docs/superpowers/plans/2026-07-31-mvp2-hotseat-coop.md`, Task 10

## 1. Контекст и цель

Task 9 плана мигрировал всю симуляционную логику под hotseat (`g->get_players()`, `g->nearest_player()`, `g->any_player_sees()` и т.д.) и завершён: все 8 файлов промигрированы, ревью чисто, оба конфига сборки зелёные на базовом уровне (1828/28988647 default, 197/62160 MULTIPLAYER).

Task 10 плана требует сыграть в hotseat-кооп не менее часа и записать наблюдения. Однако ни один из компонентов, реализованных в Tasks 1–9, не подключён к реальному игровому циклу или UI: `mp_mode_set_active()`, `g->add_player_slot()` и `mp_hotseat_do_turn()` вызываются только из тестов (`tests/hotseat_test.cpp`, `tests/hotseat_sim_test.cpp`) и из пути загрузки сейва с ключом `extra_players`. Обычный игровой цикл (`main.cpp:877`, `while( !g->do_turn() ) {}`) всегда вызывает одиночный `game::do_turn()`.

Цель этого дизайна — минимальный, permanent (не одноразовый) способ включить hotseat-режим прямо во время игры через debug-меню, чтобы Task 10 стало физически возможно выполнить.

## 2. Скоуп

### В скоупе

- Ветвление игрового цикла в `main.cpp` между `game::do_turn()` и `mp_hotseat_do_turn()` по флагу `mp_mode_active()`.
- Новый пункт debug-меню «Toggle hotseat co-op» в категории «Player» (рядом с «Control NPC»).
- Выбор стартового персонажа для слота 1 из сохранённых `.template`-файлов (тот же механизм, что и обычное создание персонажа) с fallback на «голого» дефолтного аватара.
- Один тест с тегом `[hotseat]`, проверяющий, что действие debug-меню создаёт слот и переключает флаг.
- Все новые символы — под `#if defined(MULTIPLAYER)`, как и весь код Ф0–Ф6.

### Вне скоупа

- Полноценный флоу создания персонажа для второго игрока.
- Ручное переключение активного слота из debug-меню — оно не нужно: `mp_hotseat_do_turn()` уже поочерёдно выдаёт ход каждому слоту за один вызов.
- Любые изменения `mp_hotseat_do_turn()`, `mp_tether`, `mp_bubble_anchor()` — эта логика уже реализована и протестирована в Tasks 6–8.
- Отключение hotseat-режима с удалением второго слота — слот остаётся в мире при выключении (симметрично тому, как single-player сборка уже допускает второй слот в сейве, см. Task 4).

## 3. Сводка решений

| Решение | Выбор |
|---|---|
| Точка входа в режим | debug-меню, категория «Player» |
| Стартовый персонаж слота 1 | выбор из сохранённых `.template`, либо голый авто-созданный |
| Переключение хода | автоматическое, через существующий `mp_hotseat_do_turn()` |
| Точка ветвления цикла | `main.cpp:877`, по `mp_mode_active()` |
| Постоянство изменения | закоммичено в дерево, не одноразовый патч |
| Тестовое покрытие | один `[hotseat]`-тест на само debug-действие |

## 4. Компоненты

### 4.1. `main.cpp`: ветвление игрового цикла

Текущий код:

```cpp
while( !g->do_turn() ) {}
```

Новый код (под `#if defined(MULTIPLAYER)` вокруг проверки, чтобы default-сборка даже не видела `mp_mode_active()`):

```cpp
while( true ) {
#if defined(MULTIPLAYER)
    const bool done = mp_mode_active() ? mp_hotseat_do_turn() : g->do_turn();
#else
    const bool done = g->do_turn();
#endif
    if( done ) {
        break;
    }
}
```

Поведение single-player и MULTIPLAYER-с-выключенным-режимом идентично — просто новая форма того же цикла с ранним отличием на этапе компиляции для default-сборки.

### 4.2. Debug-меню: «Toggle hotseat co-op»

Регистрация — по образцу существующего `CONTROL_NPC` (`src/debug_menu.cpp:4232`), новая запись `debug_menu_index::TOGGLE_HOTSEAT` в категории `"Player"`, под `#if defined(MULTIPLAYER)`.

Обработчик:

```
если mp_mode_active() == false:
    если g->player_slot_count() == 1:
        // второй слот ещё не создан за эту сессию
        templates := список файлов .template (как main_menu.cpp:568, load_char_templates)
        показать uilist: "None / bare avatar" + templates
        если выбран template:
            avatar &second = g->add_player_slot()
            pool_type pool
            second.load_template( chosen_name, pool )
        иначе (bare avatar):
            g->add_player_slot()   // avatar уже создан внутри add_player_slot()
    // если player_slot_count() уже > 1 (повторное включение после выключения) —
    // пропускаем создание слота, второй аватар уже существует в мире
    mp_mode_set_active( true )
    сообщение игроку: режим включён

иначе (mp_mode_active() == true):
    mp_mode_set_active( false )
    сообщение игроку: режим выключен, второй слот остаётся в мире неактивным
```

Второй слот создаётся ровно один раз за сессию: `player_slot_count() == 1` — единственное условие показа uilist выбора персонажа; при повторном включении после выключения оно уже ложно, и обработчик просто вызывает `mp_mode_set_active( true )` без создания третьего слота.

### 4.3. Тест

`tests/hotseat_test.cpp` (уже `#if defined(MULTIPLAYER)`-совместим по структуре файла, но новый тест должен сам явно жить в файле, где это уже так) получает один новый `TEST_CASE` с тегом `[hotseat]`, вызывающий обработчик debug-действия напрямую (не через реальное UI-меню) и проверяющий: `player_slot_count() == 2` и `mp_mode_active() == true` после «bare avatar» ветки, с последующим `game_test_helper::reset_player_slots()` и `mp_mode_set_active( false )` для очистки — по аналогии с каждым другим тестом в этом файле.

## 5. Обработка ошибок и граничные случаи

- **Нет сохранённых `.template`.** Список в uilist состоит из одного пункта «None / bare avatar» — обработчик не предполагает, что список непуст.
- **Повторное включение после выключения.** См. 4.2 — не создаёт второй слот повторно.
- **`load_template()` возвращает false** (повреждённый файл шаблона). Слот всё равно создан (пустым), выводится `popup`-предупреждение, режим включается — не блокируем плейтест из-за плохого файла.
